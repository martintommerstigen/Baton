## B1-H11: testable delta

**Prior:** B1 broker uses Unix SO_PEERCRED and SQLite durable `admit`/`begin_click`, but the request/reply transport is unbounded in elapsed time and accepted connections can create unlimited handler threads.

**Change:** monotonic absolute 3-second budget for complete request and reply; maximum 8 simultaneous handler threads; overflow connections closed without mutation. A malformed, partial or timed-out request never reaches `AdmissionStore.request`. No new operations, no network listener, no shell, no credentials or UI authority. Existing persisted `uncertain` and no-blind-retry semantics remain unchanged. Bytewise newline parsing intentionally does not interpret a second frame.

**Negative tests:** authorized incomplete request expires without admission; two held workers with `max_handlers=2` reject a third request; malicious slow-trickle reply cannot extend the client deadline. Existing restart/replay/pause/envelope tests still required. These tests use synthetic local Unix sockets, not Greg or ChatGPT.

**Known limits:** Unix SO_PEERCRED binds a local OS UID, not a ChatGPT conversation identity; a malicious same-UID process remains a threat. A browser DOM observation does not authenticate ChatGPT-server authorship. Timeouts may leave `admitted` or `uncertain` state requiring read-only reconciliation; never automatically resend. Even passing these negatives does not prove that B received a message or that B's correction altered C.
