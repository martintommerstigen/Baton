## B1-H06 — scoped claim and prior art

**Claim/negative:** a DOM assistant turn ID does not guarantee its text is unchanged. A first-hop `verified` ledger receipt recording only B's turn ID can be followed by a mutated `BATON_NEXT C` at the same ID. A connected-peer `SO_PEERCRED` check protects the broker channel, **not** the provenance or immutability of B's ChatGPT text.

**Prior work:** Kaja (18 Oct) already showed that duplicated archive testimony is not independent source evidence; Kaja (19 Oct) distinguished accessible observation from viable continuation; Svale (28 Oct) gave exact memory erosion/source-alias models; Riss R5 (5 Nov) distinguished preserved local hash and independent replication; Søm/Lodd (8 Nov) showed admission decisions must be serialized *before* the capacity check and that an aggregate refusal record is not a Core observation. B1 PR #21 already bound turn ID; [Ronja 2026-11-10 18:49Z](https://github.com/martintommerstigen/Baton/issues/6#issuecomment-6776212920) explicitly proposed text-hash binding and repeat read. **Classification:** prior conceptual warning + Ronja's already stated security design; this commit is a *B1-specific implementation and negative control*, NOT new physics or first discovery of source mutation.

**Changed assumption:** capture the *exact UTF-8 assistant text digest at the same UI observation that identifies B's reply*, compare against a second read before persisting an immutable first-observation snapshot in the existing SQLite ledger, and recheck the same digest/URL/turn before and after each C broker operation. Persist only chat UUID, assistant turn ID, SHA-256, extraction version, source URL and UTC timestamp; no raw assistant text. Any mismatch blocks C. If the broker may already have committed `begin_click`, mark the second hop uncertain and never blind-retry.

**Falsifier/limit:** a malicious same-UID browser/controller or DOM rewrite can still fake both reads; an unchanged hash is not cryptographic ChatGPT authorship. There remains a non-atomic gap between the final B recheck and the UI Send click, and a non-cooperating pause writer can still race the click. The new code does not solve those boundaries or install a dedicated-UID broker. Exact browser API behavior and real ChatGPT turn-ID stability are **implemented-unverified**.
