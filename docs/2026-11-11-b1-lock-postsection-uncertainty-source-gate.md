## Precisely bounded delta and falsifier

Before H16, the B1 host lock was checked against its pathname only **before** entering `submit_once`. The pre-existing NEG shows a same-UID process can rename that lock while its old file descriptor remains locked, create a new file at the same path, and obtain another exclusive flock. H16 **does not prevent** that transient split-domain race. It adds a second parent-directory and lock-file identity/type/UID/mode/nlink check **while still holding the original flock at the end of the critical section**. If the path is missing or persistently replaced, a generic `PermissionError` propagates to `wake_once`; after a possible click, the durable ledger records **uncertain**, never verified, and no automatic retry occurs after process restart.

Tests preserve the original split-domain counterexample (a second process actually acquires the replacement lock), now require the first writer to reject success, and add parent swap, path deletion and a simulated post-click swap + SQLite restart/no-resend. The check cannot prove no competing click occurred, detect a replace-and-restore entirely between checks, or protect against arbitrary same-UID browser access. It is **fail-closed evidence classification**, not a new OS locking primitive or a guarantee of exactly-once effects.
