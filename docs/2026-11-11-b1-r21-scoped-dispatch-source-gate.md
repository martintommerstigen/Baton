## Exact new application, not a new identity principle

B1's handler now prefers a callable `request_from_socket` when the installed store exposes it, passing the *accepted* AF_UNIX socket to Ronja's opt-in B5 proxy. The existing unscoped store remains available for legacy isolated tests; it is NOT an authenticated sender implementation. The CI workflow checks out Ronja R21 at immutable commit `7fb167b8dd5aee0450ee0adb9125e80697050301` into a separate test directory, without vendoring it into B1.

`test_b1_r21_scoped_dispatch.py` exercises the actual B1 socket/handler and SQLite with Ronja's actual `AuthenticatedAdmissionProxy`. Peer UID decisions are **mocked** in this test; Ronja's independent privileged Linux tests, and H19's real two-UID broker tests, do not together constitute a real combined Greg deployment. The test checks controller-as-sender denial, sender spoof, route escalation, controller-only begin_click/pause, durable uncertainty and missing kernel credentials.

### Newly exposed incompatibility (falsifiable)

**Current B1 live runner and R21 policy cannot complete the same single-hop request without a new explicit handoff.** B1's `run_verified_broker_wake.py` uses one UI-controller process to call `admit` and `begin_click`. Ronja R21 intentionally denies `admit` to the controller UID. The new negative regression records this mismatch; merely wiring `request_from_socket` does NOT make B1 deployable.

Next design decision must be source-preserving: either a separately authorized sender-UID admission after genuine existing-chat source-turn verification, or an explicitly revised R21 policy with an independently attested source-turn contract. Do not silently elevate the UI-controller's asserted sender string to authenticated ChatGPT authorship. Do not add an unreviewed second transport or release `uncertain` without independently attested assistant-turn evidence.
