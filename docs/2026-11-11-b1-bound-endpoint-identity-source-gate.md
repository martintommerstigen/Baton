## Exact B1 security delta and negative controls

**Pre-H14 counterexample:** B1 checks the service-owned parent inode and its public path, but a same-UID fault can unlink/rebind `broker.sock` **within that same parent**. An already accepted connection remains connected to the old server even though the public name now points to another socket. `parent_unchanged()` still returns true. An old accepted connection could get `admitted_not_delivered` or `click_started_uncertain` without the public endpoint being the bound socket anymore.

**H14 correction:** `Broker.endpoint_unchanged()` verifies the pinned basename is still the exact bound `st_dev/st_ino`, is a socket, is owned by the broker effective UID, is not group/world accessible, and the public parent is still the pinned parent. It is checked before accepting/dispatching and again after the store callback **before returning any receipt**. If a durable store mutation occurred during endpoint loss, no success-like response is returned, and SQLite retains the admission or `uncertain` click state to block blind retry. No socket path is unlinked unless its inode matches the bound one. This is not a cryptographic identity claim, not a proof of exact ChatGPT authorship, and does not eliminate every same-UID race.

**Deterministic tests** in `test_wake_admission_broker.py`:
- Unlink/rebind after an accepted connection reads the frame, before store dispatch: no admission, no response.
- Unlink/rebind immediately after durable admission: no success response, outstanding attempt remains, duplicate refused after restart.
- Unlink/rebind immediately after durable `begin_click`: no success response, `uncertain` state survives restart, second click refused.
