## Exact defect and bounded correction

Before H25, the older `run_chain` path called `next_target_from_reply(reply, C)` and would accept the bare `BATON_NEXT C` even though the operator-controlled plan could contain any nonempty `second_body`. B's actual source turn therefore did **not** authorize the exact bytes delivered to C. This conflicts with H17's verified-runner contract and GTRCM's source/correction distinction.

H25 changes that dispatch to `next_target_from_reply(reply, C, plan.second_digest)`, requiring an exact standalone `BATON_NEXT C sha256:<64 lowercase hex>` with **no whitespace normalization**. The existing `wake_once` already verifies `sha256(second_body.encode('utf-8')) == second_digest` before reserving or clicking C. The helper's optional argument remains for non-dispatch legacy callers; the live `run_chain` path is now strict. No extra UI writes, network listeners, shell, tokens, auto-retry or change to `PAUSE_UI_WRITES`.

Negative tests reject digestless B, wrong digest, uppercase digest, quoted/prose command, leading/trailing whitespace and newline. Positive tests preserve one A→B and one B→C **synthetic** send, exact source-turn provenance, restart reconciliation without duplicate sending, and a no-second-send outcome when B does not authorize the digest.
