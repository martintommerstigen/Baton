## Minimal opt-in implementation

`Broker(..., shared_gid=None)` preserves legacy 0600 private same-UID mode for isolated tests. Explicit `shared_gid` validates a non-root GID of which the service is a member, requires the *service-owned pinned socket parent* to have group traverse, no group write and no world permissions, chowns the newly bound AF_UNIX socket to that GID and chmods **0660**. Bound inode, owner, group and exact mode are checked at startup and before/after dispatch. Parent pathname remains pinned via directory FD. No public TCP listener, shell, token, new transport or UI write.

The production CLI rejects a distinct `--allow-uid` unless `--shared-gid` is explicitly configured. This avoids advertising a separate-UID broker that the UI worker cannot connect to.

**Example deployment contract, not a command run on Greg:** service UID `baton-broker` and UI UID `olliver` are both members of a dedicated non-root group `baton-ui`; a service-owned socket directory has group `baton-ui` and mode 0710; socket is 0660; broker's SQLite/key directory remains separate and 0700; `--allow-uid` is the *actual* UI worker numeric UID; `--shared-gid` is the dedicated group numeric GID. Every ancestor must be traversable by both participants; the OS may still deny an improperly provisioned path. The UI client independently pins the connected broker UID with SO_PEERCRED before sending bytes. The broker independently checks caller UID. Neither proves a ChatGPT source turn or bypasses `PAUSE_UI_WRITES`.
