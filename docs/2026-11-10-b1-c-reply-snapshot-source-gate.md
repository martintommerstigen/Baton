## Exact implementation delta

**Already done:** The first-hop B assistant text is captured in `wake_turn_snapshots` before `wake_once` records `verified`, and B is rechecked before C admission. The second-hop C receipt, however, previously retained only the C DOM turn ID and payload digest, **not C's first-observed assistant text digest or source URL**. In synthetic tests, an empty C assistant text could still produce a fake `Observation` and a `verified` ledger row.

**Changed:** The C target now also passes through the existing `CapturingTarget` snapshot wrapper, before second-hop ledger verification. A read-only `verify_current_reply` checks that the recorded C text SHA-256, chat URL, turn ID, nonempty text, and ledger state still agree. The chain result includes `c_reply_snapshot` (digest, URL, turn ID, extractor and UTC, **no raw assistant text**) only after this recheck. A change during initial observation leaves the attempt uncertain; a change after durable snapshot raises `SourceEvidenceChanged`, never triggering a blind resend. A verified ledger alone is insufficient to certify C's later text.

**Falsifiers:** C text mutation between DOM observation and snapshot; C text mutation after snapshot before final readback; empty C reply in the fake driver; restart read-only recheck. Tests are in `test_wake_turn_snapshot.py`. They use a synthetic driver, **not ChatGPT**.

**Residual limitations:** DOM text and turn IDs are not cryptographically authenticated ChatGPT-server evidence; source can still mutate after the final read. The broker and UI do not form an atomic transaction. The new C snapshot is O (observed evidence), not K (new influence) or I (durable learning). Actual A→B→C still requires three existing chat IDs, distinct real assistant turns, authenticated local execution, B/C independent responses, and a negative no-replay control. `PAUSE_UI_WRITES` must be independently checked before any real UI trial.
