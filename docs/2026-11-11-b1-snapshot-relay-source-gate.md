## Components and security boundary

- `b1_snapshot_relay.py`: collector's fixed source UUID and target allowlist; exact standalone `BATON_WAKE target message sha256:digest` verified twice; pause checked before and after; canonical source URL and SHA-256 only in reply. Rejects arbitrary operations, malformed frames, quoted commands, changed DOM, generation, symlink/stale socket path and untrusted pause. Uses R23 `read_authenticated_frame` to authenticate every frame segment, not merely the original connector.
- `run_b1_snapshot_collector.py`: **collector UID only** attaches to an already-running *loopback* CDP browser, with no navigation, login, UI Send or shell; exposes AF_UNIX snapshot only.
- `run_b1_snapshot_observer.py`: **separate observer UID** has no CDP dependency. Uses Ronja's existing `query_verified_broker` for authenticated snapshot relay and R22 `observe_source` witness; reads snapshot twice before witness and once after. Lost acknowledgment or post-commit change is `uncertain`, never blind retry.
- The **B1 UI controller** remains a third independent browser role and must independently verify source before any `admit→begin_click` and actual Send. The **B5 broker** is another UID. Do not conflate a snapshot, SQLite witness, broker admission, DOM turn or GitHub comment with an actual existing-chat assistant response.

The relay is *only capability-read-only for the observer if the operating system truly prevents that UID from accessing the CDP endpoint, browser profile and collector credentials*. A local socket and separate Python processes alone do **not** establish this. A compromised collector can still fabricate snapshots; a browser DOM turn ID and hash do not prove ChatGPT server authorship. No OS isolation or live ChatGPT response has been verified on Greg.

## Installation design (NOT performed on Greg)

Use four non-root UIDs: collector, observer, B5 broker, UI controller; only collector/controller may reach browser CDP and only controller may write to an existing tab. Bind CDP exclusively to loopback **and** enforce OS process/network namespace separation, because loopback alone does not prevent another local UID from connecting. Pre-create a collector-owned socket directory, non-group-writable mode `2750`, with a dedicated group shared with the observer. The AF_UNIX socket inherits that group and gets `0660`; R23 checks exact observer writer UID. Configure a separate B5 socket under the broker UID and restrict it by Ronja's policy. Never expose CDP, Unix sockets, arbitrary shell, HTTP, SSH or tokens publicly. Keep `PAUSE_UI_WRITES` in force and do not remove a stale socket until ownership and outstanding delivery have been reconciled.

Example (paths/UIDs are **illustrative only**, not installed):

```text
collector: python3 run_b1_snapshot_collector.py --source A_UUID --target B_UUID --socket /run/user/COLLECTOR_UID/b1-snapshot/relay.sock --observer-uid OBSERVER_UID --cdp http://127.0.0.1:9222
observer: python3 run_b1_snapshot_observer.py --source A_UUID --source-turn-id ACTUAL_A_TURN_ID --target B_UUID --id APPROVED_ID --payload-sha256 APPROVED_BODY_SHA256 --snapshot-socket /run/user/COLLECTOR_UID/b1-snapshot/relay.sock --collector-uid COLLECTOR_UID --broker-socket /run/user/BROKER_UID/b1/broker.sock --broker-uid BROKER_UID
```

Both commands fail closed when the pinned Ronja R23/B5 peer modules are missing. The collector's read-only behavior at the Python call level does not remove its underlying CDP write capability; only the observer's **lack of access** is the intended OS-enforced improvement.
