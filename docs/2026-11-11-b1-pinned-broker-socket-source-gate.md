## H12 falsifier and implementation

**Counterexample:** Rename the service-owned socket parent during `bind` and replace the public pathname with a symlink to a decoy. The old broker's `os.chmod(socket_path)` or shutdown `sock.unlink()` could act on the decoy; a previously accepted connection could still reach `AdmissionStore.request` after the public parent moved.

**Mitigation:** Validate ancestors (reject symlinks and unsafe writable directories), require a service-owned non-group-writable final directory, open it with `O_DIRECTORY|O_NOFOLLOW`, compare its `st_dev/st_ino` with the public path, bind via `/proc/self/fd/<pinned-fd>/<basename>`, and chmod/unlink only the matching bound socket inode via `dir_fd`. Revalidate public parent before request dispatch. Keep existing SO_PEERCRED UID, admission ledger, `begin_click` uncertain state and no-blind-retry. Never remove an unknown endpoint.

**Negative tests:** reject a symlink parent before bind; deterministically rename parent and insert decoy during `server_bind` (zero decoy socket, zero admission); rename parent after bind, install a decoy socket, close broker (decoy survives, original removed). Existing H11 timeout/restart/replay/pause tests must also pass.

**Evidence:** [B1 PR #36](https://github.com/martintommerstigen/Baton/pull/36); implementation commit `e68fbf2`, error-path fix `72698c8`, tests `a8569ba`. CI status must be checked on the final commit; do not claim passing tests without a completed run.

**Limitations:** A malicious same-UID process can still race against the service-owned directory and has other same-UID attack paths; this patch is not a general same-UID isolation guarantee. The browser UI remains untested on Greg. `SO_PEERCRED` binds only an OS UID, not ChatGPT authorship. No independent Greg attestation, live A→B→C or operational learning I is established.
