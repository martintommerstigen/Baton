## Specific delta, falsifier, and implementation

Prior art: Riss demonstrated actual UI sending, Rolf showed a missing wake edge, B1 already has broker admission and turn-text snapshots, and the desktop launcher has a relay-only read-only diagnostic. **Remaining question:** can we distinguish "relay/service responds" from "the three intended historical ChatGPT tabs are present, A's exact source turn is readable, the B5 peer is authenticated and idle, and pause is clear", *without any UI write*?

[inspect_b1_readiness.py](../inspect_b1_readiness.py) is a strictly read-only preflight:
1. Validate three distinct existing conversation UUIDs and the operator-supplied payload SHA-256; never read a private message body.
2. Check the existing pause marker fail-closed. Enumerate **already-open** browser tabs over loopback CDP; reject missing or duplicate A/B/C tabs.
3. Read only the specified A assistant turn, verify exact target+message-ID command and hash its text; do not print the text or other tabs.
4. Query B5's **connected-peer-authenticated** broker using only a status operation. Reject untrusted/missing peer, paused or outstanding broker, or generating source/target. No admission, begin-click, Send, cookie read, new chat or retry.
5. Return preflight_passed_not_delivery at most. This is **not** an A→B or A→B→C receipt.

**Important provenance correction:** B1's current BATON_WAKE B message_id source command binds only the target and message ID, **not the exact body**. The body SHA-256 is operator supplied and is checked against the UI body in existing B1 code. Therefore this probe explicitly emits source_authorizes_exact_payload=false and payload_provenance=operator_supplied_not_source_committed. It would be incorrect to call the body A-authored or source-committed. No source protocol change or claim of a new mathematical theorem is made here.

**Negative tests** in [test_inspect_b1_readiness.py](../test_inspect_b1_readiness.py): active/untrusted pause, missing or duplicate tab, missing or altered source, generating A/C, broker unavailable, broker outstanding, malformed peer status, invalid IDs/digest, and two different payload hashes under the *same* A command. The last is a deliberate negative proof of the current source-payload authority boundary, not an authorization to send arbitrary text.
