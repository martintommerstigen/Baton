## Historical equivalence and precise delta
**Already done:** B1 source-turn read/recheck, Ronja R21 SO_PEERCRED, R22 witness/admit/spend protocol, Riss earlier browser messaging. **Unresolved operational delta:** no B1-owned, separately runnable *read-only source observer* connected to the actual R22 witness interface. H21 implements that adapter, not a new protocol, physics theorem or verified existing-chat wake.

New [`observe_verified_broker_source.py`](../observe_verified_broker_source.py) accepts one already-open source ChatGPT tab via local loopback CDP, requires exactly one source UUID, an exact single assistant command with SHA-256, a clear trusted pause state, and a B5 authenticated Unix peer. It re-reads the same assistant DOM turn twice before and once after registering a witness; after a possible broker commit any mismatch/timeout is **uncertain**, never an automatic retry. It neither fills a composer nor clicks Send, launches a browser, reads cookies, creates a chat, or stores transcript content. The existing B1 controller remains responsible for independently rechecking the same source turn and for all UI write authorization.

**Security boundary:** local CDP itself can be write-capable even if this program calls only read methods. A compromised observer UID can fabricate a claim, a mutable DOM can change after the final check, and the R22 SQLite witness is not cryptographic ChatGPT authorship. Do not claim these tests establish independent source identity. Do not expose CDP or Unix socket over TCP. No shell executor is introduced. R22 and B1 may require distinct Linux UIDs, and Greg's actual service, `PAUSE_UI_WRITES`, browser selectors and permissions must be verified before any live use.
