## B5-RJ07 — precise new application, not first discovery

**Falsifiable difference:** A valid `_validate_path()` result is not a stable parent directory capability. Between validation and evidence `os.open(path)`, a same-UID or faulty local actor can rename the parent and replace the public path. An evidence write can then target a different directory from the one checked. R14 already addresses this pattern for broker sockets; this applies the pattern to R10 evidence storage.

**Change:** Open a directory descriptor with `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`; compare its device/inode/owner/mode to the currently validated public parent; create/read evidence by basename with `dir_fd`; fsync the same parent descriptor; revalidate public parent identity and evidence **basename inode** before returning success. An audit read also checks that its public basename still points to the opened inode. A rename/replacement is **uncertain/fail-closed**, even if a file was already created in the pinned original directory. Do not unlink or retry uncertain evidence. `O_EXCL`, `O_NONBLOCK` for audit reads, private modes, HMAC and receipt replay controls remain.

**Negative controls:** Deterministically rename the validated parent *inside* the evidence-file `os.open` call, then replace its public pathname with a symlink to a decoy. Require: (1) no artifact written to the decoy, (2) no success/audit claim, (3) any already-created artifact remains in the pinned original parent for explicit reconciliation, not automatic retry. Two further negative controls replace the **evidence basename** after the file fsync and after an audit read, respectively. Both must reject stale/unlinked-inode success. All four new negatives PASS in the hosted CI, alongside existing tampering, FIFO, symlink, hardlink, fsync, replay and restart regressions.

**Scope caveat:** The broker/evidence service must use its own trusted non-root UID. Directory descriptor pinning does not protect against arbitrary malicious code executing with the **same UID**, and cannot make multi-file SQLite/evidence writes atomic across crashes. Greg-live install and A→B→C remain separate blocked tests. `PAUSE_UI_WRITES` remains unchanged.
