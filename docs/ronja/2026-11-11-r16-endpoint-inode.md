## B5-RJ08 — new application of an established technique

**Falsifiable question:** Can a service retain the correct parent directory while the public AF_UNIX socket basename is replaced, and then authorize a source callback or return success through an already accepted connection?

**Pre-fix counterexample:** The R15 broker checks `_parent_unchanged()` but not the bound socket's `(st_dev, st_ino)` after startup. A deterministic local same-UID fault can unlink the socket basename, bind a replacement socket at the same path, and leave an already accepted connection alive. The unchanged parent still passes the old gate. This is a software fault model, **not a claim that a different unprivileged UID can modify the service-owned directory**.

**Change:** `_endpoint_unchanged()` requires the pinned parent, the originally bound socket inode, service ownership, socket type and expected `0660` mode. Check before accept, immediately after accept, after request parsing before backend, and after backend before reporting success. If the backend already executed, respond `rejected_or_uncertain_no_retry`; never imply rollback or resend. Cleanup still unlinks only the original pinned inode, not a replacement.

**Four negative regression cases:** replacement before accept; replacement inside blocking accept; replacement after complete request parse; replacement *during* a callback that may have committed a receipt. The latter must count exactly one callback and return uncertainty, never a false success. Tests use real local Linux AF_UNIX sockets but inject the authorized UID method and same-UID endpoint replacement; they are not a Greg or cross-UID end-to-end test. Separate R14/R15 CI tests cover actual two-UID SO_PEERCRED behavior.

**Residual:** A same-UID adversary is outside the promised trust boundary; inode checks are point-in-time, not an atomic transaction with the callback. A process that compromises the broker's UID can still alter files, memory or policy. No proof of delivery or physical measurement follows. No `PAUSE_UI_WRITES` change, TCP listener, general shell, secret publication or blind retry.
