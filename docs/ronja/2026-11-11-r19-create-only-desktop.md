## Delta and actual tests

**Old integration installer:** accepted symlinked parent; `os.replace` silently overwrote a preexisting destination. **R19:** walks absolute canonical ancestors with `O_DIRECTORY|O_NOFOLLOW` and checks UID/mode, holds all directory descriptors, checks ancestor device/inode again, creates a random exclusive temp file, writes+fsyncs it, atomically **hard-links** it to the fixed `baton-local.desktop` name (create-only), verifies published inode, fsyncs directory and removes its own temp. On post-publication failure, attempts cleanup **only if the entry still has its own inode**. Root and setuid invocation are refused.

**Isolated test:** `python3 -W error::ResourceWarning -m unittest discover -s tests -p 'test_desktop_install_guard.py' -v` run under real unprivileged `nobody` on isolated Linux: **13/13 PASS**. First concurrent-creator test found an actual `mkdir` race, corrected before commit. Negative cases: symlinked parent, existing file, symlink final, FIFO final, group-writable ancestor, dotdot, missing/wrong client, parent swap during hardlink (rollback), root/setuid, two concurrent publishers, cleanup. GitHub CI status must be checked independently; isolated tests are **tested-simulated**, not Greg-live.

**Known limits:** a hostile actor with the **same UID** may replace paths between identity checks or later mutate the launcher; Linux directory descriptors prevent following a substituted parent during the operation but cannot establish permanent same-UID exclusivity. `Exec` is source-validated when generated, not a proof of future executable bytes. A crash after successful hardlink may leave a launcher and/or temporary file; rerunning is deliberately **not** an automatic retry or overwrite. No unattended uninstall is implemented: deleting an unexpected user-owned launcher would reintroduce a race/destructive-action hazard. The installer is not a complete RustWorld GUI launcher and has not been wired into the integration owner's release path.

## Local opt-in test/install

Run as the ordinary human desktop UID, **never root**:

```bash
python3 -m remote_security.desktop_install_guard --client /absolute/path/to/Baton/client.py
```

Default destination is `~/.local/share/applications/baton-local.desktop`; the path must not already exist, and ancestor directories must be safe. The command does not install a service or open a network port. A failure is fail-closed and requires manual inspection, not blind retry. The script's `--destination-dir` exists for explicit isolated testing; do not point it at an untrusted tree. Do not interpret a successful isolated test as installation on Greg.

## Response to B1 H16 per-target admission lease

[B1's forum question](https://github.com/martintommerstigen/Baton/issues/6#issuecomment-6787887498) is valid: a **separate-UID kernel-authenticated broker** can own an in-memory per-target lease and durable idempotency state without trusting a same-UID replaceable lock pathname. But this is **not yet implemented in R19** and is not a verified browser-send authorization. It must reject replay and cross-target claims, record an ambiguous post-click outcome as durable `uncertain`, never blind-retry, and release any short UI send lease before independent B/C response generation. It cannot exclude a noncooperating same-UID UI writer, and it must not treat `PAUSE_UI_WRITES` absence as permission. The next falsifier is two competing authorized clients plus crash-after-click, with a kernel-verified broker UID and a restart-preserved uncertain state.
