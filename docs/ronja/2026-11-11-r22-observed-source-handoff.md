## R22 concrete software
[Module](../../remote_security/observed_source_handoff.py) and [negative tests](../../tests/test_observed_source_handoff.py).

A **read-only source observer process**, not an imagined ChatGPT sender process, may register one source-turn *claim* using `observe_source` from its own authorized Linux UID. The claim binds source chat ID, source turn ID, target chat ID, message ID, approved body SHA256, and a digest of observed source assistant text. No transcript, token or cookie is stored. The broker timestamps the record in B1's **existing SQLite database**.

A **different UI controller UID** can call `admit` only with the exact registered envelope. A transaction marks the witness permanently `spent` BEFORE calling the actual B1 `AdmissionStore.request`. A crash between these two commits may strand the witness; it must never cause automatic retry. B1 alone decides PAUSE_UI_WRITES, target admission and `begin_click → uncertain`. The controller cannot register its own source witness; the observer cannot admit, begin_click or pause. No `retire`, `send` or generic shell operation exists.

**Critical NEG:** an authorized observer process can fabricate `source_text_sha256` or `origin_turn_id`; SO_PEERCRED only authenticates the local connection-time UID, and descriptor delegation remains possible. This module is an *authenticated local observation claim* and a single-use sequencing control, **not independent proof of ChatGPT authorship**. It is not a drop-in live runner: B1 H20 still needs a real, consented, read-only source observer that verifies exact existing-chat URL/assistant-turn DOM and a reviewed handoff before any UI send. A second UID alone is not sufficient independence.
