## What changed and why it is deliberately not retirement

[Library](../../remote_security/retirement_quarantine.py) records an exact B1 envelope and a separately claimed UI receipt as a **candidate**, not an authorization. The only durable state is `quarantined_not_retired`. It never opens a browser, changes B1's admission SQLite, releases a target, or sends a request. A duplicate is deduplicated; conflicting same-target evidence remains quarantined; cross-target reuse of user/assistant turn IDs is rejected. The candidate binds conversation, message, origin turn, sender, payload SHA-256, observed user turn and observed assistant turn.

`record_from_socket` reads `SO_PEERCRED` from the accepted Linux AF_UNIX socket and rejects an attestor with the broker's UID or a UID other than the configured independent attestor. A JSON `sender_id` cannot override the kernel UID. The internal `_record_authenticated` test hook accepts synthetic UIDs **only for isolated policy tests**. The separate UID is still **not** proof that an actual ChatGPT DOM turn was observed. Before any future real retirement, B1 must authenticate the observer's actual UI capability and transactionally recheck the still-current admission and pause/uncertain state. This library supplies neither that attestation nor an automatic `retire` operation.

The SQLite quarantine directory must be private (service-owned, 0700) and separate from attestor/browser UIDs. Symlinked ancestors, noncanonical paths, symlinked databases, hardlinks and loose permissions are rejected at initialization. The SQLite pathname is not pinned by dirfd through every operation; a malicious same-UID process or privileged host process can still race it. **Do not install with same-UID untrusted writers.** No secrets or private transcripts are stored.

## Test evidence and falsifiers

- Isolated Linux `python3 -W error::ResourceWarning -m unittest discover -s tests -p 'test_retirement_quarantine*.py' -v`: **29/29 PASS** (27 ordinary tests, two privileged cross-UID tests) in the local working container. These use **synthetic UI receipts**. Linux kernel UID checks use real forked UIDs 20002/20003 on a temporary socket; no Greg or browser.
- Negative controls: wrong peer UID, same broker/attestor UID, source/target/payload substitution, missing/colliding turn IDs, cross-target turn reuse, replay, restart, simultaneous same-target candidates, conflicting new message, symlink ancestor/database, path traversal, world-readable parent/database. No test calls a UI writer.
- [Trusted push CI](../../.github/workflows/remote-envelope.yml) runs the two real-UID tests under `sudo` **only** for trusted repository push; untrusted PR code is not run as root. Ordinary suite runs without privilege. Record actual hosted CI run and commit SHA separately after verification; do not infer success from a green previous R19 run.
- **Falsifier for future retirement:** even a syntactically correct `verified` receipt from a kernel-authenticated attestor may be fabricated by that attestor or may refer to a stale DOM. If independent UI observation is not demonstrated, the B1 admission must remain `uncertain` after crash/restart. This is an intentionally unsolved authorization boundary.
