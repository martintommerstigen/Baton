## Claim B5-RJ06 — directory pathname validation is not a durable socket binding

**Prior:** R11 verified parent ownership/mode/ancestors at construction, and R13 saved the bound socket inode for rollback. But R13 still called `sock.bind(str(self.path))` and later `chmod`, `lstat`, `unlink` using the **mutable absolute pathname**. An attacker able to rename/replace the directory *after the check* could redirect the bind or cleanup. This is a conventional Linux filesystem race, **not** a new GTRCM theorem. R13's existing inode-only rollback remains necessary but is insufficient if the path resolves through a replaced parent.

**Delta implemented:**
1. Save the validated parent's `(st_dev, st_ino)` in the broker. At startup, recheck all ancestors, open the directory with `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`, and compare the descriptor's `fstat` identity to the pinned identity.
2. Bind through `/proc/self/fd/<dirfd>/<socket-name>` on Linux. The kernel resolves the socket relative to the **pinned directory descriptor**, not the possibly replaced public parent pathname.
3. Use `dir_fd`-relative `stat`, `chmod(follow_symlinks=False)`, and `unlink` for the socket. Recheck that the public pathname still reaches the original directory after `listen`, and before accepting another request. If not, fail closed and clean up only the original socket inode inside the original directory.
4. Retain distinct non-root UID, `SO_PEERCRED`, fixed source IDs, bounded framing, absolute deadlines, no TCP, no arbitrary shell, no UI sends, no blind retry, and `PAUSE_UI_WRITES`.

**Deterministic negative controls:** (a) replace parent with a new same-owner/same-mode inode before start; reject, no socket created; (b) rename parent and insert a symlink to a decoy **inside the patched `socket.bind` call**, after initial validation; bind remains anchored to original directory, then rollback removes it; no socket appears in decoy; (c) rename parent after listening and create a replacement socket at the public path; broker refuses `accept_once`, cleanup removes only original inode, leaves replacement untouched. All three passed in hosted Linux CI. The old R13 replaced-socket test was updated for the new fd-relative API and passed.

**Threat boundary:** A malicious same-UID process can still interfere with the service-owned directory and with same-UID state; this is not a defense against full service-UID compromise. A root adversary is out of scope. The parent pathname may be swapped and restored between checks; fd anchoring prevents redirecting the actual bind to the decoy, but this does not establish end-to-end availability. If `/proc/self/fd` is unavailable, bind fails closed. Linux CI tests do not prove Greg installation or independent physical observation.
