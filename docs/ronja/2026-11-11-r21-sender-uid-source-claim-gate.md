## B5-RJ14 exact code delta
[Module](../../remote_security/admission_sender_scope.py) implements an immutable, explicit process UID → asserted sender ID mapping plus per-sender allowed target routes. The broker, sender A, sender B and UI controller must use distinct non-root UIDs. The proxy rechecks the broker's effective UID on every request, not only at construction. Only an authorized sender UID may request an admit for its claimed sender ID and permitted target. Only the controller UID may request begin_click or pause; status is scoped read-only. Invalid or extra fields, wrong SHA, unknown UID, cross-target route escalation, TCP/non-AF_UNIX, and a broker process running under the wrong UID fail closed.

The [proxy](../../remote_security/admission_sender_scope.py) extracts the UID from the accepted Linux AF_UNIX socket using SO_PEERCRED. The legacy unscoped request method raises PermissionError. The B1 handler must explicitly change its dispatch from store.request(req) to store.request_from_socket(self.request, req), and configure B1 allowed_uids to the policy's distinct sender/controller UIDs. This change is NOT made to B1-owned files; it requires an independently tested B1 integration before deployment. No new transport, network listener, generic shell or UI writer is introduced.

**Further historical counterexample:** [Andreas G28 original code](https://github.com/martintommerstigen/GTRCM/blob/research/andreas-g28-multichannel-common-mode-2026-11-04/experiments/gaia_self_influence/andreas_2026_11_04/g28_multichannel_common_mode.py), blob 4d52f81511a5170256fb8e69ce1ac65c4e20f5cb, explicitly demonstrates that common-mode channels can agree on a wrong candidate. Multiple UIDs are not independent proof if they share a delegated socket, compromised UI, or common origin. This is reuse of Andreas's earlier NEG, not a new theorem.\n\n**Crucial negative:** SO_PEERCRED reports credentials captured at AF_UNIX connection time; an authorized process can delegate an already-connected file descriptor (fork/SCM_RIGHTS) to another process. This adapter does not authenticate the identity of each later writer or prevent deliberate authorized delegation. A compromised same-UID process can also submit claims. An authorized sender UID can still invent an origin_turn_id within its own namespace. The policy deliberately returns uid_scoped_claim_only, NOT source_verified. Independent existing-chat source-turn evidence and B1's durable state machine remain required. A controller UID does not prove a real ChatGPT assistant turn either. No retirement, automatic retry or Send authorization is granted.
