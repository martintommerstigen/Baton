## Implemented and tested

[Source](../../remote_security/sealed_unix_channel.py) `seal_unix_channel(sock, endpoint=..., peer_uid=...)` is a **second, irreversible seccomp layer** for a dedicated non-root observer **after** R25, R24 preflight and connection to exactly one source-pinned pathname AF_UNIX stream.

1. Require distinct non-root observer and collector UIDs. Validate actual connected peer through `SO_PEERCRED`, AF_UNIX stream family, peer pathname, inode, owner and mode. Walk parent directories with `O_NOFOLLOW`; reject path aliases and world-writable socket.
2. Reject any other open socket FD, including a preexisting undeclared connected CDP socket. Probe R25's *kernel effects* on disposable sockets, never by consuming live snapshot bytes.
3. Install another libseccomp filter denying **all** future `socket`, `socketpair`, `connect`, `bind`, `listen`, `accept`, `accept4`, message-based FD transfer, pidfd_getfd, ptrace, process_vm and io_uring. Block `socketcall` where resolvable. The already-connected authorized stream continues via `send/recv`.
4. Confirm real kernel denial after installation. Any error terminates the dedicated worker; no automatic reconnect, no UI-write authorization.

[Tests](../../tests/test_sealed_unix_channel.py) use real Linux kernel seccomp and separate actual UIDs 29101/29102, with a synthetic echo broker. Negative controls: missing R25, wrong peer UID, forged socket pathname owner versus real `SO_PEERCRED`, extra inherited socket, traversal, symlinked parent, new AF_UNIX/socketpair, and `exec` persistence. The separate real-R25 integration test runs when the pinned R25 module is present.

**Local exact-source result:** 8 PASS / 1 SKIP (real R25 not present in standalone local workspace), Linux 6.18.57, Python 3.13.5, root harness dropping to distinct non-root UIDs. Local source Git blob SHAs were matched to uploaded GitHub files. [Dedicated CI workflow](../../.github/workflows/ronja-r26-sealed-unix.yml) runs the real pinned-R25 case and the full cross-UID suite under Ubuntu with sudo. ## Negative finding / integration boundary

This does **not** integrate into H24 unchanged: H24 opens fresh snapshot and R22/R23 broker sockets and repeats R24 preflight; after R26 sealing, these operations would be denied. The B1-owned runner must first adopt **one preconnected, authenticated, framed/multiplexed snapshot channel**, perform all necessary preflight before sealing, and preserve R22's durable one-time witness semantics and `PAUSE_UI_WRITES`. A source-only echo test is not a valid B1 witness or an existing ChatGPT assistant turn.

This denies **future connection syscalls**, not arbitrary file reads or actions through the one already trusted broker. It does not prove the collector cannot lie, stop a privileged host from replacing process memory, or prevent a malicious broker from forwarding CDP on the authorized channel. Keep the collector/observer distinct and restrict broker operations to the exact read-only snapshot schema. Do not grant general shell, UI send, new endpoints or retry after uncertain delivery.

**Next falsifier for B1:** under separate UIDs, can one long-lived authenticated R23 channel carry two ordered, exact-schema snapshots and a one-use R22 witness while the R26 observer has zero new-connect capability? Then deliberately expose a same-group undeclared AF_UNIX CDP socket and prove connection fails, without weakening `PAUSE_UI_WRITES`. No claim of a Greg install until actually run on Greg.
