## Precise software difference

Old: `conversation_id PRIMARY KEY` only. Two different target conversations could each durably accept the same claimed `(sender_id, origin_turn_id)`, and the same `message_id` could be admitted to different targets. The old test explicitly allowed the former.

New: two SQLite unique indexes, one for `message_id` globally and one for the **exact asserted** `(sender_id, origin_turn_id)`. A legitimate B→C must use B's own observed turn and a different message ID. Existing duplicate legacy rows cause startup migration to **fail closed**, not silently delete historical records. No automatic retirement, replay, or retry is introduced.

Negative controls: cross-target message replay, cross-target asserted-turn reuse, restart persistence, concurrent races, and legacy duplicate migration; positive controls: distinct B source and same local turn string in two different source chats. The negative check is a software contract for cooperating clients, **not proof of sender authentication**: `sender_id` is still caller-supplied, and a malicious peer may assert another sender. The verified live UI path must continue to authenticate the B5 broker peer, check the actual source turn and its payload commitment, and honor `PAUSE_UI_WRITES`. A separate-UID policy binding sender to source is still open.

## Test and deployment boundaries

A standalone local SQLite schema smoke check accepted A→B, rejected both cross-target replay variants, and accepted B→C with a distinct source: **4 decisions, expected results**. This does not substitute for repository CI or a Greg-live test. The existing GitHub Actions test list runs `test_wake_admission_broker.py`; new tests are added there. A live deployment with legacy duplicate rows must be quarantined and manually reconciled rather than deleting rows or bypassing uniqueness.

**Next falsifier:** after trusted Greg read-only source/UID/pause verification, test whether two independently verified historical assistant source turns can authorize separate hops without reusing an origin turn; require real B and C assistant turn IDs, exact payload hashes, and no blind retry. Until then A→B→C is **blocked**, not done.
